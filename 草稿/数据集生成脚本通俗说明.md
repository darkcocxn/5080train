# 数据集生成脚本通俗说明

对应脚本：

`数据集生成-steel01主体-steel02阻尼器-周期约束-三阶段主动采样-3到7层-尾部增强版.py`

## 一句话说明

这个脚本做的事情可以理解成：

> 先准备很多“建筑结构方案”和很多“地震波”，再把每一个结构方案放到某一条地震波下面，用 OpenSees 做一次动力时程分析，最后把结构参数、地震波特征、最大层间位移角、是否屈服、是否分析失败等结果写成 CSV 数据集。

也就是说，最终数据集里的每一行不是凭空生成的，而是一次真实的 OpenSees 仿真结果。

## 一条数据样本是什么

一条样本大致等于：

```text
一个结构模型 + 一条地震波 + 一次 OpenSees 分析结果
```

结构模型包含：

- 楼层数：3 到 7 层。
- 楼层质量：从若干离散值里选。
- 层高：从若干离散值里选。
- 主体结构层刚度：从若干离散值里选。
- 主体结构材料：Steel01。
- 阻尼器材料：Steel02。
- 阻尼器屈服力：500 到 2500 kN 之间取 5 个离散档。
- 阻尼器安装位置：每一层装或不装，例如 `(0,0,1)` 表示 3 层结构只在第 3 层装阻尼器。

地震波包含：

- 地震波文件路径。
- 地震波步长和长度。
- PGA、RMS、CAV、能量代理值、持续时间、主频等特征。
- 一张对应的时频图路径，如果是文本波文件。

分析结果包含：

- 最大层间位移角 `max_drift_ratio_raw`。
- 量化后的层间位移角 `max_drift_ratio_q1e4`。
- 主体 Steel01 是否屈服。
- 阻尼器 Steel02 是否屈服。
- 阻尼器峰值力。
- 最大响应发生在哪一层。
- 分析是否成功、失败原因、是否非收敛。

## 数据从哪里来

脚本会先找地震波输入。

优先使用：

```text
C:/Users/12200/project/Dategeneral/Newdatabase/rare_waves_scaled.h5
```

如果这个 HDF5 文件不存在，就会退回到地震波文本目录，例如：

```text
Origin-earthquake-file/6000-uniform-scale-0.1-1.0
Origin-earthquake-file/6000
```

如果是 HDF5，脚本从 `scaled_acceleration` 里面逐条读取地震波。

如果是 `.txt` 文件，脚本直接读取文本里的加速度序列。

地震波文件里的加速度按 `g` 保存，真正喂给 OpenSees 时会乘以 `9.81`，变成 `m/s^2`。

## 先把地震波分成 train / val / test

这个脚本不是先全部算完再随机切分数据，而是先把地震波本身分成三个波池：

- 训练集波池 `train`
- 验证集波池 `val`
- 测试集波池 `test`

这样做的目的很明确：

> 避免同一类地震波在训练、验证、测试里分布太偏，也避免事后切分导致数据泄漏或评估不稳定。

具体做法是：

1. 对每条地震波提取特征，例如 PGA、RMS、CAV、能量、持续时间、主频等。
2. 用这些特征做标准化。
3. 用 KMeans 把地震波聚成 8 类。
4. 每个聚类里面再按比例分到 train / val / test。

默认比例是：

```text
train : val : test = 0.70 : 0.15 : 0.15
```

脚本会把波特征保存成：

```text
*_wave_features.csv
```

把波池划分保存成：

```text
*_wave_split.csv
```

如果下次运行时发现地震波列表没变，它会直接复用这些缓存文件。

## 再生成结构参数

结构参数不是完全乱选，而是用 LHS，也就是 Latin Hypercube Sampling，中文常叫拉丁超立方采样。

通俗理解：

> 不希望样本都挤在某一小块区域，而是尽量把质量、层高、刚度、阻尼器强度这些参数铺开，让整个参数空间都被覆盖到。

脚本每次生成结构时，会同时考虑 4 个主要采样维度：

- 楼层质量。
- 层高。
- 主体刚度。
- 阻尼器屈服力。

然后再随机搭配阻尼器安装位置。

当前离散档位大致是：

| 参数 | 取值方式 |
| --- | --- |
| 楼层数 | 3、4、5、6、7 层 |
| 楼层质量 | 50、70、90、110、130、140 t |
| 层高 | 2.5、2.8、3.2、3.5、3.8、4.0 m |
| 主体刚度 | 6 个离散档 |
| 阻尼器屈服力 | 500 到 2500 kN 的 5 个几何级数档 |

顶层质量和顶层刚度会乘以 `0.85`，表示顶层比标准层轻一些、柔一些。

## 结构会先过周期筛选

结构参数生成出来以后，不是马上拿去做地震响应分析。

脚本会先建立一个不含附加阻尼器的主体结构模型，计算一阶自振周期 `T1`。

如果：

```text
T1 > 0.9 s
```

这个结构就被剔除。

也就是说，只有周期满足要求的结构，才会进入后面的高保真动力时程分析。

这样可以避免生成一批明显不符合设定约束的结构。

## OpenSees 里怎么建模

脚本用的是简化剪切型集中参数模型。

建模方式可以这样理解：

- 每一层是一个节点。
- 楼层质量加在节点上。
- 每一层之间用 `zeroLength` 弹簧连接。
- 主体结构弹簧材料是 `Steel01`。
- 如果某层装了阻尼器，就再并联一个 `Steel02` 阻尼器弹簧。

主体 Steel01 的屈服力不是随便采样的，而是由刚度和屈服位移角推出来：

```text
Fy_story = K_story * floor_height * frame_yield_drift_ratio
```

其中默认屈服位移角是：

```text
frame_yield_drift_ratio = 0.01
```

也就是 1% 层间位移角。

这意味着：

> 主体结构越硬，它的屈服力也越大，而不是刚度和屈服力互相脱节。

阻尼器 Steel02 的屈服力 `Fy_add` 则从 500 到 2500 kN 的离散档中选。

## 每次动力分析怎么做

对每个样本，脚本会：

1. 根据结构参数建立 OpenSees 模型。
2. 加入 Rayleigh 阻尼，目标阻尼比默认是 5%。
3. 读取地震波。
4. 把地震波作为 `UniformExcitation` 输入。
5. 用 Newmark 方法做瞬态动力分析。
6. 每一步都读取各层位移。
7. 计算每一层的层间位移角。
8. 记录整个时程里的最大层间位移角。
9. 判断主体 Steel01 和阻尼器 Steel02 是否屈服。

如果 OpenSees 在某一步不收敛，脚本不会直接崩掉，而是把这条样本标记为失败，并记录：

- 失败步数。
- 失败时间。
- OpenSees 返回码。
- 失败类别。

## 数据集不是一次随机生成完，而是分阶段生成

这个脚本的核心是“三阶段主动采样 + 尾部补样”。

通俗说：

> 先均匀撒一批样本，再让机器学习模型猜哪里最不确定，然后重点去算那些更有价值、更容易出大响应的样本。

### Stage A：先均匀铺开

Stage A 是初始样本。

它会对 3 到 7 层分别生成一批结构，用 LHS 尽量覆盖整个结构参数空间。

每个结构会搭配多条训练集地震波。

这一阶段的目的不是追求极端响应，而是先让训练集有一个比较完整的基础覆盖。

### Stage B：主动学习补样

Stage B 开始使用已经算出来的训练集结果。

脚本会训练一个小的“委员会模型”，包括：

- RandomForestRegressor
- ExtraTreesRegressor
- RandomForestClassifier
- ExtraTreesClassifier

这些模型不是最终要训练的业务模型，而是用来帮脚本选样本的临时模型。

它们会对候选样本预测：

- 最大层间位移角大概是多少。
- 预测结果之间分歧大不大。
- 阻尼器是否屈服的不确定性大不大。
- 当前数据集中类似响应区间是不是样本太少。

然后脚本优先选择那些：

- 模型之间意见不一致的样本。
- 当前数据集中比较稀缺的响应区间。
- 阻尼器屈服判断不确定的样本。

这些被选中的候选样本，才真正送进 OpenSees 做高保真分析。

默认 Stage B 做 3 轮。

### Stage C：专门加强大位移尾部样本

Stage C 是尾部强化。

这里的“尾部”指的是：

```text
max_drift_ratio_raw 比较大的样本
```

比如接近或超过：

```text
0.01、0.02
```

普通随机采样很容易生成大量小响应样本，但大位移、大损伤、主体屈服的样本往往比较少。

所以 Stage C 会有意识地偏向高风险组合：

- 更高楼层。
- 更大质量。
- 更低刚度。
- 更短层高。
- 更少阻尼器安装数量。
- 更接近周期上限的结构。
- 更强的地震波。

同时，脚本会优先使用地震波强度排名靠前的一部分强震波。

这样可以增加训练集中大层间位移角样本的数量。

## Stage D：尾部补样

除了 Stage A、B、C，脚本后面还有一个尾部补样过程。

训练集对应：

```text
stage_d_tail_topup
```

验证集和测试集对应：

```text
val_tail_topup
test_tail_topup
```

这个步骤会先检查当前数据集里尾部样本够不够。

主要看三个目标：

- `max_drift_ratio_raw >= 0.01` 的成功样本数。
- `max_drift_ratio_raw >= 0.02` 的成功样本数。
- 主体 Steel01 屈服样本数。

默认最低目标是：

| 数据集 | `drift >= 0.01` | `drift >= 0.02` | 主体 Steel01 屈服 |
| --- | ---: | ---: | ---: |
| train | 500 | 80 | 500 |
| val | 40 | 8 | 40 |
| test | 40 | 8 | 40 |

如果已经满足目标，就跳过后续补样。

如果不满足，就继续生成高风险候选结构，搭配强震波，再用主动学习评分挑出最值得算的样本。

这个版本叫“尾部增强版”，重点就是为了避免：

- 训练集里 `0.02` 附近样本太少。
- 验证集和测试集几乎没有大响应样本。
- 模型评估时看不出尾部泛化能力。

## 验证集和测试集怎么生成

验证集和测试集不直接复用训练集的地震波。

它们使用前面单独划出来的 `val` 和 `test` 波池。

生成方式是：

1. 用空间填充方式生成验证或测试结构。
2. 每个结构搭配若干条对应波池里的地震波。
3. 做 OpenSees 分析。
4. 如果尾部样本不足，再做对应 split 的尾部补样。

这样做的目的，是让验证集和测试集也有足够的大响应样本，不能只评估小响应区域。

## 输出文件在哪里

脚本会把结果写到项目下的 CSV 目录，优先使用：

```text
C:/Users/12200/project/Dategeneral/CSV-dataset
```

如果原来有：

```text
C:/Users/12200/project/Dategeneral/数据集
```

也可能复用这个目录。

主要输出包括：

```text
*_train.csv
*_val.csv
*_test.csv
*_wave_features.csv
*_wave_split.csv
*_summary.json
```

其中：

- `train.csv` 是训练集。
- `val.csv` 是验证集。
- `test.csv` 是测试集。
- `wave_features.csv` 是地震波特征表。
- `wave_split.csv` 是地震波划分表。
- `summary.json` 是本次生成结果的统计汇总。

文件名里会带有运行标签 `RUN_TAG`，默认包含当前时间。

| `split` | train、val 或 test |
| `stage` | 样本来自哪个生成阶段 |

| `floor_mass` | 楼层质量 |

| `damper_layout` | 阻尼器安装位置 |
| `period_1_sec` | 裸结构一阶周期 |
| `period_compliant` | 周期是否满足上限 |
| `wave_pga` | 地震波 PGA |
| `wave_intensity_score` | 地震波强度排序得分 |
| `max_drift_ratio_raw` | OpenSees 算出的最大层间位移角 |

## 脚本支持断点续跑

这个脚本是流式写盘的。

也就是说，它不是所有样本都算完才一次性写 CSV，而是每累计一定数量的结果就追加写入文件。

默认每 200 行写一次。

如果脚本中途停止，下次再运行时会读取已有 CSV，收集已有的 `sample_id`。

已经存在的样本会被跳过。

所以它适合长时间批量仿真，也比较适合中断后继续跑。

## 为什么要用主动采样

如果完全随机生成样本，会出现两个问题：

1. 大量样本都是普通小响应，信息量重复。
2. 大位移、大损伤、屈服附近的样本太少。

但是训练结构响应代理模型时，最难学、也最重要的往往正是这些区域：

- 接近屈服。
- 接近失效。
- 位移角比较大。
- 阻尼器是否屈服边界不清楚。

所以脚本用了一个更省仿真次数的策略：

> 先算一批基础样本，再用已有结果训练临时模型，让临时模型指出哪些候选样本最值得继续算。

这样可以在有限的 OpenSees 计算量下，得到更有用的数据集。

## 整体流程图

```text
读取超参数
    ↓
寻找地震波文件或 HDF5 数据
    ↓
提取地震波特征
    ↓
KMeans 聚类地震波
    ↓
按聚类分配 train / val / test 波池
    ↓
生成结构参数
    ↓
检查裸结构一阶周期是否 <= 0.9 s
    ↓
结构 + 地震波 组合成分析任务
    ↓
OpenSees 动力时程分析
    ↓
写入 train / val / test CSV
    ↓
主动学习挑选更多高价值样本
    ↓
尾部补样，补足大位移和主体屈服样本
    ↓
输出 summary.json
```

## 用最通俗的话总结

这个脚本不是简单地“造数据”，而是在自动做一套结构地震响应试验：

1. 先把地震波按特征分好类，保证训练、验证、测试都有代表性。
2. 再生成不同楼层、质量、层高、刚度、阻尼器强度和安装位置的结构。
3. 不合周期要求的结构先剔除。
4. 合格结构和地震波两两组合，送进 OpenSees 计算。
5. 每次计算得到最大层间位移角、屈服状态、失败信息等。
6. 先均匀生成一批，再用主动学习挑难点继续算。
7. 最后专门补大位移尾部样本，让数据集不仅有普通情况，也有接近损伤和屈服的情况。

最终得到的 CSV 可以用来训练结构地震响应代理模型，也可以用来评估模型在普通响应和大响应尾部区域的预测能力。
