
关键结论：

| Group | Train unique | Val unique | Test unique | Train-test overlap | All-three overlap | 结论 |
|---|---:|---:|---:|---:|---:|---|
| sample_id | 66755 | 3280 | 3112 | 0 | 0 | 跨 split 无重复样本 ID |
| txt_path | 163 | 17 | 14 | 0 | 0 | 跨 split 无重复地震波路径 |
| structure_signature | 16331 | 881 | 802 | 0 | 0 | 跨 split 无重复结构签名 |
| scenario_signature | 66755 | 3280 | 3112 | 0 | 0 | 跨 split 无重复“地震波+结构”组合 |
| wave_cluster | 8 | 5 | 4 | 4 | 3 | cluster 有重叠，但不是具体波路径重叠 |

论文意义：

- 目前 split 比普通随机 split 更干净。
- 可以较有力地支持“测试集不含训练集出现过的具体 `txt_path` 地震波路径”。
- 也可以支持“测试集不含训练集出现过的结构签名或地震波+结构组合签名”。
- 但 `wave_cluster` 有重叠，因此不能说测试集来自完全未见的地震波类型/簇分布；只能说具体波路径未重叠。

建议论文表述：

```text
The locked test set contains no overlapping sample IDs, ground-motion paths,
structural signatures, or ground-motion-structure scenario signatures with
the training set.
```

不建议表述：

```text
The test set is fully out-of-distribution in all seismic characteristics.
```

因为 `wave_cluster` 层面仍有重叠。

论文风险：

- 跨 split 无重复，这是好事。
- 但 split 内存在重复 `sample_id` / `scenario_signature`。
- 如果这些重复行是完全重复样本，会影响有效样本数和统计检验。
- 如果这些重复行是同一工况的重复模拟或不同输出记录，需要在数据说明中解释。

后续建议：

- TODO2 后追加一个轻量 dedup audit：比较重复 key 的所有输入/目标是否完全一致。
- 在最终论文统计检验中，优先按 `scenario_signature` 或 `txt_path` 聚合，避免重复行造成置信区间过窄。

关键解释：

- train 有大量 `>=0.005` 样本，但没有 `>=0.010` 样本。
- val 有 152 个 `>=0.010` 样本，且 max 达到 0.014465。
- test 没有 `>=0.010` 样本，max 只有 0.007362。
- train/test 均没有 `>=0.015` 和 `>=0.020` 样本。

论文可支撑结论：

- 可以报告 locked test 的 IID/generalization 平均误差。
- 可以报告 test 上 `>=0.005` 的轻中度 tail 表现。

论文暂时不能支撑结论：

- 不能声称模型已经在 `>=0.010`、`>=0.015`、`>=0.020` 高漂移场景中通过 locked test 验证。
- 不能声称模型能可靠预测屈服或接近失效场景。
- 不能仅凭当前 locked test 支撑 high-drift safety claim。

下一步必要动作：

- TODO10 中必须构建 high-drift stress benchmark。
- 或者生成/保留包含 `>=0.010`、`>=0.015`、`>=0.020` 的外部测试集。

## 14. 当前结论

TODO2 已完成。当前数据 split 的好消息是：train/val/test 之间没有 `sample_id`、`txt_path`、结构签名或 scenario signature 的跨集合重叠，这能显著增强 locked test 的可信度。

主要风险也很清楚：locked test 的高漂移和主体屈服覆盖不足，不能支撑强 high-drift safety claim；split 内存在重复 `sample_id` / `scenario_signature`，后续统计检验应按 group 聚合或先做去重等价审计。

因此，当前数据可以用于严肃的平均误差和轻中度 tail 测试，但若论文要强调工程安全、高漂移可靠性或屈服工况泛化，必须在 TODO10 建立额外 high-drift / yielded / OOD benchmark。
