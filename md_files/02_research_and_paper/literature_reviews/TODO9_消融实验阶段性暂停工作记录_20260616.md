## 2. 本次脚本修复

### 2.1 zero scalar patch 兼容性

问题：`image_only_zero_scalar` 在测试端调用 `build_scalar_feature_frame(..., expected_feature_names=...)` 时，原 patch 只接受 `(df, layout_width)`，导致关键字参数不兼容。

处理：在 `update/run_ablation_suite.py` 中将 patch 函数改为：

```python
def zeroed_scalar_feature_frame(df, layout_width, *args, **kwargs):
    feature_df, feature_names = original(df, layout_width, *args, **kwargs)
```

影响：只作用于消融 runner 中的输入 patch，不影响原训练脚本。

### 2.2 Windows torch.save 1224 写入错误

问题：`no_tail_loss | seed=20260616` 训练到第 4 轮后，原始训练脚本在保存 `best_2dcnn_model.pth` 时触发 Windows 文件写入错误：

```text
RuntimeError: [enforce fail at inline_container.cc:745] . open file failed with error code: 1224
```

处理：未修改原始 `2dcnnv11/2dcnnv11.py`，而是在 `update/run_ablation_suite.py` 内新增 `install_resilient_torch_save()`，仅对消融进程局部 monkey patch：

- `torch.save` 先写入临时文件；
- 成功后用 `os.replace` 原子替换目标文件；
- 对 `error code: 1224`、文件占用、权限瞬时错误进行退避重试；
- 不影响其它正在运行的训练任务。

验证：修复后从 `no_tail_loss | seed=20260616` 重新续跑，越过第 4 轮保存点并完成测试。

## 5. 阶段性观察

1. `image_only_zero_scalar` 明显退化，说明小波图像分支单独不足以支撑当前任务，结构标量与布局特征是核心信号来源。
2. `scalar_only_blank_image` 明显弱于完整模型与大多数消融变体，说明图像分支/多模态表示仍提供有效补充。
3. `no_wave_scalar_features` 当前三 seed 主指标最好，但其 q90/q95 尾部误差并不最优。阶段性解释应谨慎：CSV 中的波形统计特征可能与小波图像分支信息冗余，甚至对当前 locked test 有轻微噪声，但不能据此直接宣称应删除该模块；需要 paired bootstrap、阈值尾部指标和跨 split/外部验证共同判断。
4. `no_image_augmentation` 当前主指标和尾部指标都很强，提示当前图像增强不是主要性能来源；也可能是 locked test 与训练分布接近，增强带来的稳健性收益未充分显现。论文中应将其表述为“在该协议下未观察到显著收益”，而不是“增强无用”。
5. `no_tail_loss` 整体 MAE 与 full model 接近，但尾部 MAE 并未占优。该结果支持论文中单独报告 tail/safety 指标，避免只用整体 MAE 得出过强结论。
6. `concat_fusion` 与 `full_model` 在三 seed 上非常接近，说明融合结构的贡献需要配对样本检验与误差分布图支持，不能只凭均值判断。
7. `no_weighted_sampler` 与 full model 接近，但第 3 seed 明显偏差更大，可能体现 sampler 对 seed 稳定性的边际作用。
